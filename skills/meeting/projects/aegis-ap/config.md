## 프로젝트 개요

- AEGIS-AP: AEGIS-AP의 로그 기반 분석 역량을 기반으로, 이상감지, 예측분석 기능을 단계적으로 확장하여 WiNG의 핵심 활용 가치를 내재화하는 것을 목표로 한다.
- 주요 범위: WiNG 기능 내재화, VOC 기반 합성 CDR/KPI 데이터 생성, Agent Workflow/NeMo Toolkit 검토, 품질 조기경보 PoC
- 정리 원칙: AEGIS-AP는 상위 프로젝트 카드로 유지하고, 하위 실험은 PoC 단위로 구분한다.

## 요약 형식 규칙

- 회의 요약은 AEGIS-AP 관점의 문제 정의, 설계 결정, 데이터/검증 흐름으로 정리한다.
- CDR/KPI 관계, incident_type, 고객사 범위, 제품명/솔루션명은 혼동 가능성이 높으므로 원문 표현과 근거를 함께 남긴다.
- 액션 아이템은 명사형으로 간결하게 쓰고, 담당자가 명확하면 이름과 직급을 함께 적는다.
- 결정사항은 결정 내용과 이유를 함께 남긴다.

## 작성 우선순위

1. 팀원이 바로 볼 수 있도록 `한 줄 요약`, `결정사항`, `액션 아이템`을 먼저 명확히 쓴다.
2. 전체 대화록은 포함하지 않는다.
3. 단순 발언 나열보다 “무엇이 결정됐고 다음에 누가 무엇을 해야 하는지”를 우선한다.
4. 논의가 길어도 팀 공유용 문서는 과도하게 늘리지 않고 핵심 근거만 남긴다.
