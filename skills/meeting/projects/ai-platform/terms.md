## 조직 및 프로젝트 용어

- LIG: 그룹 또는 조직을 줄여 부른 표현. 단독으로 나오면 LIG Accuver와 LIG System 중 어느 조직인지 문맥으로 확인한다.
- LIG Accuver: 당사. PoC를 주관·리드하고 고객 대응을 담당한다. 회의에서 `LIGA`로 줄여 부르기도 한다.
- LIG System: AI 플랫폼과 기술 구현을 지원하는 조직. 고객과 직접 대면하는 역할은 어렵다고 정리되었다. 회의에서 `LIGS`로 줄여 부르기도 한다.
- LG U+: 고객사. PoC에서 확인할 기능과 운영 요구사항을 제시한다.
- AI 플랫폼 PoC: ML 이상탐지, RCA 연계, MLOps, 워크플로우 및 인프라 활용 가능성을 검증하는 과제.
- Track 1 / Track 2: PoC 구현 경로를 구분하기 위해 사용된 표현. 정확한 담당과 산출물 범위는 회의별로 확인한다.

## 통신·RCA 용어

- RCA (Root Cause Analysis): 장애 또는 이상 현상의 원인을 분석하는 절차. 이 프로젝트에서 어디까지를 RCA 결과로 볼지는 별도 확인한다.
- Rule-based RCA: 사전에 정의한 규칙으로 원인을 판정하는 기존 RCA 방식. Java 구현이 언급되었다.
- CDR (Call Detail Record): 통신 이벤트 또는 세션의 상세 기록. PoC의 이상탐지 입력 데이터로 논의된다.
- XDR: 통신 이벤트·세션 관측 레코드 계열을 가리키는 표현. 실제 스키마와 CDR과의 관계는 데이터 기준으로 확인한다.
- XDB: 회의에서 데이터 연계 대상 시스템명으로 언급됨. 정식 명칭·데이터 범위·SDB와의 차이는 확인 필요.
- KPI (Key Performance Indicator): 네트워크 상태나 품질을 나타내는 측정 지표.
- Attach 성공률: 단말의 망 접속 절차가 성공한 비율을 나타내는 KPI.
- S1 Attach: 이번 PoC에서 성공률 감시와 RCA 분석의 시작 지점으로 사용한 시나리오. 다른 인터페이스 민원에도 같은 분석 방식이 적용되는지는 별도 확인한다.
- S6a: S1 Attach 성공률 저하의 하위 원인을 추적하는 과정에서 HSS 인증 실패와 연계해 언급된 인터페이스. PoC에서는 S1과 한 시나리오로 묶여 있다.
- MME (Mobility Management Entity): LTE 코어망에서 단말의 이동성·인증·세션 제어를 담당하는 장비. 이번 회의에서는 IP별 KPI 유사도와 RCA 원인 후보를 비교하는 디멘션으로 사용되었다.
- 이상탐지: CDR/XDR 또는 집계 KPI에서 정상 패턴과 다른 상태를 찾는 과정.
- Trigger: 이상탐지 또는 RCA 흐름을 시작하는 조건이나 이벤트. 실제 CDR 기반 조건은 확인이 필요하다.
- Probe: 네트워크 데이터를 수집·전달하는 장비 또는 구성요소를 가리키는 일반 용어. 이 프로젝트의 실제 경로와 역할은 확인한다.

## ML·MLOps 용어

- Isolation Forest: 데이터의 분할 격리 특성을 이용하는 비지도 이상탐지 알고리즘. PoC의 기본 모델 후보로 논의되었다.
- Feature Engineering: 원천 데이터에서 모델 입력 특성을 생성·변환하는 작업.
- MLflow: 실험, 모델, 아티팩트 및 배포 흐름을 관리하는 MLOps 도구.
- MLOps: 모델 개발, 학습, 배포, 모니터링 및 갱신을 운영하는 체계.
- Model: 학습된 이상탐지 로직과 추론 결과를 만드는 구성요소. `ModelFlow`와 동일한 표현으로 간주하지 않는다.
- Test case: PoC 기능을 재현하고 검증하기 위해 준비한 입력 조건과 예상 결과.

## 플랫폼·인프라 용어

- Dify: LLM 애플리케이션과 워크플로우를 구성하고 실행하는 플랫폼.
- Agent Builder: 플랫폼에서 agent 기반 동작 흐름을 구성하는 기능 또는 도구를 가리키는 표현.
- Workflow: 데이터 입력부터 모델 실행, RCA 및 보고서 생성까지 연결한 처리 흐름.
- LLM 보고서: LLM을 이용해 분석 결과와 근거를 자연어로 정리한 결과물.
- OpenRouter: 여러 Public LLM API를 중계해 사용하는 서비스. LG U+ 내부 데이터와 실제 IP를 외부로 전송하지 않도록 사용 범위를 구분한다.
- TelecomGPT-R1: LG U+ 내부 환경에서 RCA 보고서 텍스트 생성 후보로 언급된 통신 도메인 LLM. 실제 제공 모델명과 품질은 확인이 필요하다.
- Tech Summit: AI 플랫폼 이상탐지·RCA·MLOps 데모의 외부 시연 대상으로 언급된 행사. 고객 전용 KPI 명칭과 실제 IP는 노출하지 않는다.
- Ontology: 개념과 관계를 구조화해 도메인 지식을 표현하는 모델.
- Semantic Layer: 원천 데이터 위에 업무 개념과 의미 관계를 일관되게 제공하는 계층.
- Neo4j: 그래프 데이터베이스. RCA 관계 데이터 또는 지식 구조 표현에 활용 후보로 언급된다.
- Cypher: Neo4j에서 그래프 데이터를 조회·변경하는 쿼리 언어.
- GPU: 모델 학습 또는 추론에 사용하는 병렬 연산 장치.
- MIG (Multi-Instance GPU): 하나의 지원 GPU를 여러 격리된 GPU 인스턴스로 분할하는 기능.
- Kubernetes: 컨테이너 기반 워크로드의 배포와 운영을 관리하는 오케스트레이션 플랫폼.
- Cloudera Data Platform (CDP): LG U+의 기존 데이터 플랫폼 문맥에서 언급된 Cloudera 플랫폼.

## 회의록 작성 규칙

- 확정 용어와 `확인 필요 용어`를 분리한다.
- `확인 필요 용어`는 자동 교정하지 않고 원문, 후보 또는 의미, 확인할 내용, 근거 회의를 함께 기록한다.
- `ModelFlow`와 `MLflow`처럼 발음이 비슷해도 같은 제품이나 기능으로 단정하지 않는다.
- LIG Accuver와 LIG System의 역할을 혼동하지 않는다.
- RCA는 이상탐지 자체, 원인 후보 생성, 규칙 실행, 결과 보고를 구분해 기록한다.
- CDR, XDR, XDB, SDB는 서로 바꿔 쓰지 않고 데이터 스키마와 시스템 구분이 확인된 경우에만 확정한다.
- 기술의 `현재 구현`, `PoC 적용 예정`, `검토 후보` 상태를 명시한다.
- 미확정 직급, 소속, 일정, GPU 구성 및 고객 요구사항을 추정하지 않는다.
